<objective>
Fix the Playwright MCP server registration in all three workspace templates so the
baked bundled chromium is actually used at runtime.

Each template's `startup_script` writes a `cfg.mcpServers.playwright` entry whose
`args` array is `["-y", "@playwright/mcp@latest"]`. With no `--browser` flag,
`@playwright/mcp` defaults to the `chrome` channel (branded Google Chrome at
`/opt/google/chrome/chrome`), which is not installed — the Dockerfiles bake
Playwright's bundled chromium into `/ms-playwright`. Containers also have no
`$DISPLAY`, so the browser must run headless. The result today: the first
`browser_navigate` fails with
`Chromium distribution 'chrome' is not found at /opt/google/chrome/chrome`.

The fix (verified live this session): append `"--browser", "chromium", "--headless"`
to the args array in all three files. This is the only change.

Purpose: Make self-serve UI testing via the Playwright MCP work out of the box.
Output: 3 edited `main.tf` files, one identical one-line change each, committed atomically.
</objective>
