<objective>
Add `zlib1g-dev` to `templates/java-fullstack/Dockerfile` so GraalVM
`native-image` compiles can resolve the `libz.so` dev symlink out of the box.

Purpose: The base image ships the runtime `libz.so.1` but NOT the dev symlink
`/usr/lib/x86_64-linux-gnu/libz.so`. GraalVM `native-image`'s link step passes
`-lz` to the linker, which resolves that dev symlink; without it the native
build fails at link time. `zlib1g-dev` installs the missing dev symlink
system-wide.

Output: Modified `templates/java-fullstack/Dockerfile` with a dedicated,
well-commented apt install block for `zlib1g-dev`.
</objective>

Add a new SYSTEM-WIDE apt install block for the `zlib1g-dev` package to
`templates/java-fullstack/Dockerfile`.

PLACEMENT (recommended: a dedicated, self-documenting block — NOT folded into
an existing block): Insert the new block after the MemPalace CLI block (which
ends at the line `&& rm -rf /var/lib/apt/lists/*` immediately before the
`# ── GitHub CLI (gh) ──` header) and before the GitHub CLI header. Any
position among the root-owned system blocks (i.e. after `USER root` on line 30
and before the final `USER coder` on line 172) is functionally correct because
apt installs into `/usr` regardless of ordering; place it after MemPalace and
before GitHub CLI for readability.

Justification for a dedicated block over folding into the MemPalace or Node
apt-get install: the file uses a strict one-purpose-per-block convention, each
with its own `# ── … ──` header explaining WHY the block exists. `zlib1g-dev`
is a native-linker dependency unrelated to MemPalace (a Python memory CLI) or
Node; folding it into either block would bury a build-critical dependency under
an unrelated header and obscure its purpose for the next maintainer. A dedicated
block matches the documented, comment-heavy style of every other block in this
Dockerfile.

BLOCK STYLE: Match the existing apt-block idiom used by the MemPalace and gh
blocks exactly:
  - Open with a `# ── zlib (libz.so dev symlink for GraalVM native-image) ──`
    style header comment (box-drawing rule to roughly match the column width of
    the neighbouring headers), followed by 2-4 comment lines of prose.
  - The prose comment must explain: the base image ships the runtime
    `libz.so.1` but not the dev symlink `/usr/lib/x86_64-linux-gnu/libz.so`;
    GraalVM `native-image` passes `-lz` to the linker at its link step, which
    resolves that dev symlink; `zlib1g-dev` provides it system-wide; and note
    that this lands in `/usr` (outside the volume-shadowed `/home/coder` mount),
    matching the SYSTEM-WIDE note in the file header.
  - The RUN command must follow the same chained form as the MemPalace/gh
    blocks: `RUN apt-get update && apt-get install -y --no-install-recommends
    zlib1g-dev && apt-get clean && rm -rf /var/lib/apt/lists/*` (use the same
    line-continuation `\` layout as the neighbouring blocks).

Do NOT touch any other block, the JDK/Maven install, `USER root`/`USER coder`
lines, or the Docker-CLI comment block. Do NOT install under `/home/coder`.
Do NOT add a runtime `zlib1g` line — only the dev package `zlib1g-dev` is
needed (it depends on and pulls the matching runtime as required).
