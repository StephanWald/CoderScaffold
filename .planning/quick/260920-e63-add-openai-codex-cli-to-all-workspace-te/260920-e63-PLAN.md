<assumption_delta_decision>
Add-alongside (recommended, non-blocking). The per-owner shared volume keeps its established
identity: it mounts at `~/.claude-shared` and the Docker volume is named `coder-<owner-uuid>-claude`.
Codex config nests INSIDE it at `~/.claude-shared/codex`. This is accepted naming debt: renaming the
volume or its mount path would orphan every existing owner's Claude/MemPalace config. A second AI
agent CLI does not justify stranding owner data. No rename/promotion.
</assumption_delta_decision>

<scope_decisions>
**Piece 3 (OPENAI_API_KEY passthrough) — OUT OF SCOPE.** No clean symmetric pattern exists to mirror:
ANTHROPIC_API_KEY flows through the `claude-code` Terraform module input, but Codex is a plain
Dockerfile-installed CLI with no module, and there is no ANTHROPIC_API_KEY entry in `coder_agent.env`
to mirror. `.env.example` carries no API_KEY entries at all. Wiring OPENAI_API_KEY would mean
introducing a new variable + env plumbing pattern from scratch in 7 templates — intrusive, not a
mirror. Codex's ChatGPT sign-in auth persists in the shared `~/.codex/auth.json` (delivered by this
plan), which is the primary auth path, so nothing is blocked by deferring the API-key route.
</scope_decisions>
