<objective>
Fix the EACCES crash of the `feynman` CLI in the research workspace template. The
package hard-codes its runtime setup/lock paths to its own npm install root
(`/usr/lib/node_modules/@companion-ai/feynman/.feynman/...`), which is root-owned in the
image; `FEYNMAN_HOME` does not relocate them. So every invocation by the runtime user
`coder` fails mkdir-ing the setup lock. The fix is to `chown` the package install dir to
`coder` in the Feynman RUN layer, after the build-time `feynman --version` pre-warm.

Purpose: `feynman` must actually run for the developer (user `coder`) in a live workspace.
Output: A one-line `chown` added to the Feynman layer in `templates/research/Dockerfile`,
with an updated comment explaining why, verified by a real docker build + run as `coder`.
</objective>
